# DMI College Hostel Management PWA — Authentication & Authorization Plan

## 1. Authentication Flows

The application supports two distinct authentication pathways on `/login`:

### 1.1 Student Pathway
- **Identifiers**: Student ID (`CSE-3-001`), Register Number (`310621104001`), or Email (`rahul.kumar@gmail.com`).
- **Initial Password**: Set during 3-step sign-up on `/register` or default enrollment password (`DmiCE@1202`).
- **Target Route**: Directs to `/student/dashboard`.

### 1.2 Staff / Admin Pathway
- **Identifier**: Official Gmail ID (`staff.*@gmail.com`, `hod.*@gmail.com`, `warden.*@gmail.com`, etc.).
- **Initial Password**: Temporary 10-character password generated by Chief Warden on `/warden/staff-accounts` (`STAFF_INITIAL_PASSWORD = "Staff@123"`).
- **Temporary Password Enforcement**:
  - Newly created staff accounts have `mustChangePassword: true`.
  - Upon successful login, the application redirects immediately to `/change-password`.
  - The user must submit a strong permanent password satisfying length, uppercase, lowercase, numeric, and symbol rules.
  - Upon success, `mustChangePassword` is cleared and user is redirected to `getHomeRoute(role)`.

## 2. JWT Token Claims (Supabase Auth)

The JWT minted by the backend must embed custom user claims:
```json
{
  "sub": "b2c3d4e5-f6a7-4b8c-9d0e-1f2a3b4c5d6e",
  "email": "warden.dmi@gmail.com",
  "user_metadata": {
    "role": "warden",
    "name": "Dr. John Xavier",
    "must_change_password": false,
    "status": "Active"
  },
  "app_metadata": {
    "role": "warden",
    "permissions": [
      "passes.view", "passes.approve", "passes.reject",
      "gate_passes.issue", "rooms.manage", "staff.manage"
    ]
  }
}
```

---

## 3. Account Disabling & Security Invalidation

- If an account has `status === "Disabled"`, backend auth must immediately reject login with code `ACCOUNT_DISABLED`.
- If an admin disables an account while a session is active, the JWT refresh endpoint must revoke active refresh tokens and reject subsequent requests.
